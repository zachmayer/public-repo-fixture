# Contributing

Thanks for your interest in contributing. These guidelines help keep changes easy to review and the project easy to maintain.

1. **Keep changes focused.** Each pull request should address one problem or add one feature. Smaller, self-contained changes are reviewed faster and are easier to revert if needed.
2. **Describe what and why.** In your pull request, explain the problem you are solving and the approach you took, and note anything a reviewer should look at closely.
3. **Check your work before requesting review.** Run the existing tests and linters, and confirm your change works as described. Update documentation that your change affects.
