# Contributing

Thanks for your interest in contributing! To keep reviews fast and the history easy to follow, please:

1. **Discuss larger changes first.** Open an issue describing the problem and your proposed approach before starting significant work, so the direction can be agreed on up front.
2. **Keep each pull request focused.** Make one logical change per PR, and describe what changed and why in the PR description.
3. **Check your work before requesting review.** Run the existing tests and linters locally, and add tests for new behaviour where practical.
